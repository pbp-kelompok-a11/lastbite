# AI Disclosure & Analisis Kritis Keterbatasan AI

Dalam pengerjaan Proyek LastBite pada Modul Eco Impact (Impact Journal & Green Wallet), saya menggunakan AI sebagai referensi teknis untuk penyusunan arsitektur logika metrik dampak lingkungan, integrasi endpoint AJAX visualisasi, pembuatan komponen dasbor interaktif, dan penulisan rangkaian unit test.

Tools yang Digunakan: ChatGPT

Bagian yang Dibantu AI:
1. Menyusun struktur dasar endpoint API (`summary_api` dan `logs_api`) untuk agregasi data kalkulasi makanan terselamatkan, reduksi emisi karbon (CO2), dan penghematan biaya.
2. Memberikan referensi template komponen UI visual dasbor (kartu metrik Jejak Baikmu, diagram batang tren bulanan, kartu status gamifikasi Waste Warrior, dan riwayat log).
3. Menyusun kerangka awal fungsi JavaScript asinkron (`fetch`) untuk memuat data riwayat log dan memperbarui statistik tanpa memuat ulang halaman secara penuh (full page reload).
4. Menyusun draf rangkaian unit test untuk menguji kode respon HTTP (200, 302, 400, 403, 404), validasi form, hak akses antar-peran, dan fungsi agregasi metrik.


### Analisis Kritis Keterbatasan AI & Perbaikan Manual:

1. Integritas Data Transaksi vs Manipulasi Log (Data Tampering): AI awalnya mengizinkan seluruh log diedit melalui form yang sama. Saya menganalisis bahwa log turunan `Order` berstatus Completed harus bersifat imutabel sebagai bukti transaksi, sehingga saya memblokir hak edit/hapus pada log otomatis (`order__isnull=False`) dan hanya mengizinkannya pada log penyelamatan mandiri.
2. Formula Rasio Konversi Emisi Karbon (CO2): AI mengusulkan konstanta emisi global statis tanpa konteks ilmiah yang jelas. Saya mengkritisinya karena limbah makanan di Indonesia didominasi organik berkadar air tinggi; saya menetapkan faktor emisi backend terverifikasi (1.9 kg CO2 per kg) agar estimasi dampak lingkungan tidak menyesatkan (greenwashing).
3. Celah Keamanan Insecure Direct Object References (IDOR): AI membuat endpoint edit dan hapus hanya memfilter berdasarkan `ImpactLog.objects.get(pk=id)`. Saya mengidentifikasi celah ini dan secara manual mengunci kueri dengan `user=request.user` agar pengguna tidak dapat memanipulasi atau menghapus catatan milik pengguna lain via modifikasi URL/payload.
4. Kalkulasi Selisih Penghematan Finansial (Quantity Multiplication): AI mengkalkulasi penghematan hanya dari selisih harga satuan `(original_price - discounted_price)`. Saya mengoreksi logika ini karena satu pesanan dapat berisi beberapa porsi; rumus wajib mengalikan selisih harga dengan kuantitas pesanan agar nominal pada Green Wallet tidak defisit atau keliru.
5. Resolusi Relasi Kosong (Null Traversal) Nama Toko: AI hanya membaca field `notes` untuk menampilkan nama merchant pada kartu log, menyebabkan log otomatis berlabel placeholder `[Nama Toko]`. Saya merombak view untuk menelusuri relasi `log.order.store.name` secara defensif dengan fallback bertingkat sebelum beralih ke `notes`.
6. Celah Manipulasi Klien pada Level Gamifikasi: AI menyarankan penentuan tingkatan Waste Warrior dihitung di JavaScript frontend berdasarkan isi DOM. Saya menolak pendekatan ini karena rentan dimanipulasi melalui inspeksi elemen browser; seluruh kalkulasi progres level dan batas perolehan lencana (badge) saya sentralisasi di backend `summary_api`.
7. Metode Destruktif Tanpa Proteksi CSRF: AI menghasilkan aksi penghapusan log menggunakan tag tautan `<a>` berbasis HTTP GET. Saya mengkritisi pelanggaran standar HTTP dan risiko CSRF/prefetching ini, lalu merombaknya menjadi request berproteksi decorator `@require_POST` dengan token CSRF yang valid.
8. Kebocoran Isolasi Styling CSS (Global Scope Pollution): AI menulis aturan CSS yang menimpa tag `body` dan sistem tipografi secara global di `eco_impact.css`, merusak tampilan navbar dan footer halaman lain. Saya membatasi cakupan (scoping) seluruh selector secara ketat hanya di dalam container berawalan `.eco-`.
9. Kerapuhan URL Routing Tombol Aksi (Error 404): AI merender tautan tombol edit pada frontend ke rute `/edit/<uuid>/`, padahal rute terdaftar di `urls.py` menggunakan prefiks `/logs/edit/<uuid>/`. Saya menambahkan URL alias pada modul `urls.py` agar aksi tombol pensil tidak menghasilkan error 404.
10. Sanitasi Tag HTML & Penanganan XSS pada Catatan: AI berasumsi field `CharField` otomatis bebas dari celah skrip injeksi. Saya menambahkan sanitasi karakter berbahaya dan batasan panjang string pada field catatan manual guna mengantisipasi eksekusi skrip jahat saat log dirender kembali via AJAX.
11. Pencegahan Anomali Data (Negative & Zero Values): AI membiarkan input berat makanan dan nominal penghematan bernilai nol atau negatif lolos ke database. Saya menambahkan validator `MinValueValidator(0.01)` pada level model dan form untuk menjaga keabsahan statistik agregat.
12. Inefisiensi Query Agregasi (In-Memory Python Loops): AI menghitung akumulasi total dampak dengan memuat seluruh objek model ke memori lalu menjalankan loop manual di Python. Saya mengoptimalkannya dengan memanfaatkan agregasi langsung di database menggunakan Django ORM `aggregate(Sum(...))` demi efisiensi performa server.
13. Asumsi Keliru Dukungan Browser pada Web Share API: AI membuat tombol bagikan pencapaian langsung memanggil `navigator.share` tanpa validasi. Saya menambahkan blok fallback otomatis berupa penyalinan tautan ke clipboard beserta notifikasi toast agar fitur tidak macet di browser desktop yang tidak mendukung Web Share.
14. Inkonsistensi State Metrik Pasca-Input AJAX: AI menyarankan memuat ulang halaman secara penuh (full page reload) setiap kali pengguna menambah log manual. Saya menolak saran ini dan membangun siklus asinkron di mana respons sukses AJAX langsung mentrigger fetch ulang `summary_api` agar kartu metrik di atasnya ter-update instan tanpa mereset posisi scroll.
15. Query Filter Rentang Waktu Rentan Perbedaan Zona Waktu: AI memfilter data mingguan dan bulanan menggunakan manipulasi string tanggal lokal mentah. Saya memperbaikinya dengan query ORM `date__gte` berbasis `django.utils.timezone.now()` dan `timedelta` agar sinkron dengan zona waktu server.
16. Implementasi Diagram Batang 6 Bulan Mandiri: AI mengusulkan impor pustaka charting pihak ketiga yang berat dan memperlambat first load. Saya menggantinya dengan implementasi CSS Grid Bar Chart mandiri yang menghitung rasio persentase dinamis langsung dari respons JSON backend, menjaga aplikasi tetap ringan tanpa dependensi luar.
17. Cakupan Pengujian Keamanan & Kondisi Batas (Edge Cases): AI awalnya hanya menyusun unit test skenario ideal (happy path) dengan asumsi pengguna selalu valid. Saya memperluasnya secara manual menjadi 16 pengujian komprehensif, mencakup proteksi akses Guest (302 redirect), isolasi data antar-pengguna (403/404), dan akurasi formula matematis metrik dampak.
